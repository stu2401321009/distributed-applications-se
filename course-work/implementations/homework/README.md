## Описание на системата

**Система за резервация на учебни зали в университет**

Системата позволява на студенти и преподаватели да резервират учебни зали за определен ден и час. Потребителите могат да разглеждат наличните зали, да правят резервации и да следят техния статус. Администраторът управлява залите, потребителите и одобрява или отхвърля постъпилите резервации.

Системата е изградена с разделение на три роли: **Student**, **Teacher** и **Admin**. Студентите и преподавателите имат равни права в системата — и двете роли могат да разглеждат зали и да правят резервации. Единствено администраторът може да добавя и деактивира зали, да управлява потребители и да одобрява резервации.

## Автентикация и сигурност

Системата използва **JWT Bearer Token** автентикация. При успешен вход клиентът получава токен, който трябва да изпраща при всяка следваща заявка в HTTP заглавката:

```
Authorization: Bearer {token}
```

Токенът е валиден **24 часа**. Единствено endpoints `/api/auth/login` и `/api/auth/register` са публични — всички останали изискват валиден токен.

Паролите **никога** не се съхраняват в явен вид — само техният bcrypt хеш се записва в базата данни.

---

## Обработка на грешки

Системата използва централизиран middleware за прихващане на грешки. Клиентът **никога** не получава суров stack trace. Всички грешки се връщат в стандартизирания формат **RFC 7807 (Problem Details)**:

```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "Невалидни данни",
  "status": 400,
  "detail": "Полето 'email' трябва да е валиден email адрес.",
  "instance": "/api/auth/register",
  "errors": {
    "email": ["Полето е задължително."],
    "capacity": ["Стойността трябва да е поне 1."]
  }
}
```

Полето `errors` присъства само при валидационни грешки (HTTP 400) и съдържа списък с грешки по конкретни полета.

## Страници и сортиране

Всички endpoints, които връщат списъци, задължително поддържат страници и сортиране. Параметрите са общи за всички списъчни заявки:

| Параметър   | Тип      | По подразбиране | Описание                                |
| ----------- | -------- | --------------- | --------------------------------------- |
| `page`      | `int`    | 1               | Номер на страницата, започва от 1       |
| `pageSize`  | `int`    | 10              | Брой елементи на страница, максимум 100 |
| `sortBy`    | `string` | `createdAt`     | Поле, по което се сортира               |
| `sortOrder` | `string` | `asc`           | Посока на сортиране: `asc` или `desc`   |

Отговорът при списъци винаги е в следния формат:

```json
{
  "items": [
    /* масив с елементи на текущата страница */
  ],
  "totalCount": 47,
  "page": 1,
  "pageSize": 10,
  "totalPages": 5
}
```

---

#### `POST /api/auth/register` — Регистрация

Създава нов потребителски акаунт. Достъпен без автентикация. Новият потребител може да бъде само `Student` или `Teacher` — ролята `Admin` не може да се регистрира по този път.

**Входни параметри (тяло на заявката — JSON):**

| Поле            | Тип      | Задължително | Валидации                                            |
| --------------- | -------- | ------------ | ---------------------------------------------------- |
| `firstName`     | `string` | да           | минимум 2, максимум 50 символа                       |
| `lastName`      | `string` | да           | минимум 2, максимум 50 символа                       |
| `email`         | `string` | да           | валиден email формат, максимум 100 символа, уникален |
| `password`      | `string` | да           | минимум 8, максимум 100 символа                      |
| `role`          | `string` | да           | `Student` или `Teacher`                              |
| `facultyNumber` | `string` | не           | максимум 20 символа                                  |
| `phoneNumber`   | `string` | не           | максимум 20 символа                                  |

**Изходни данни при успех (HTTP 201):**

Обект с JWT токен, дата на изтичане и данни за новосъздадения потребител.

**Грешки:** `400` невалидни данни — `409` email вече съществува — `500` вътрешна сървърна грешка

---

Автентикира потребителя и връща JWT токен. Достъпен без автентикация.

**Входни параметри (тяло на заявката — JSON):**

| Поле       | Тип      | Задължително | Валидации                                  |
| ---------- | -------- | ------------ | ------------------------------------------ |
| `email`    | `string` | да           | валиден email формат, максимум 100 символа |
| `password` | `string` | да           | минимум 8 символа                          |

**Изходни данни при успех (HTTP 200):**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresAt": "2026-06-16T14:30:00Z",

    "id": 1,
    "firstName": "Иван",

  }
```

**Грешки:** `400` невалидни данни — `401` грешен email или парола — `500` вътрешна сървърна грешка

#### `GET /api/reservations/{id}` — Детайли за резервация

Връща пълна информация за конкретна резервация, включително данни за залата и потребителя. **Достъп: Admin или собственикът на резервацията.**

**Входни параметри (path):** `id` — идентификатор на резервацията.

**Изходни данни при успех (HTTP 200):**

```json
{
  "id": 15,
  "room": { "id": 3, "name": "А201", "building": "Корпус А", ... },
  "user": { "id": 1, "firstName": "Иван", "lastName": "Иванов", ... },
  "startTime": "2026-06-15T09:00:00Z",
  "endTime": "2026-06-15T11:00:00Z",
  "purpose": "Групова работа по проект",
  "status": "Pending",
  "notes": "Нуждаем се от проектор",
  "attendeeCount": 25,
  "createdAt": "2026-05-08T14:30:00Z"
}
```

**Грешки:** `401` — `403` — `404` — `500` вътрешна сървърна грешка

#### `POST /api/reservations` — Създаване на резервация

Създава нова заявка за резервация. Системата автоматично проверява дали залата е свободна. Новата резервация получава статус **Pending** и изчаква одобрение от Admin. **Достъп: всички автентикирани потребители.**

**Входни параметри (тяло на заявката — JSON):**

| Поле            | Тип        | Задължително | Валидации                                             |
| --------------- | ---------- | ------------ | ----------------------------------------------------- |
| `roomId`        | `int`      | да           | минимум 1, залата трябва да съществува и да е активна |
| `startTime`     | `DateTime` | да           | трябва да е в бъдещето                                |
| `endTime`       | `DateTime` | да           | трябва да е след `startTime`                          |
| `purpose`       | `string`   | да           | минимум 5, максимум 200 символа                       |
| `attendeeCount` | `int`      | да           | минимум 1, не може да надвишава капацитета на залата  |
| `notes`         | `string`   | не           | максимум 500 символа                                  |

**Бизнес валидации (проверяват се на сървъра):**

- `startTime` трябва да е в бъдещето
- `endTime` трябва да е след `startTime`
- `attendeeCount` не може да надвишава `capacity` на избраната зала
- Залата не трябва да има одобрена (`Approved`) резервация, която се припокрива с посочения период

**Изходни данни при успех (HTTP 201):** Обект `ReservationResponse` с новата резервация.

**Грешки:** `400` — `401` — `404` залата не е намерена — `409` залата е заета — `500` вътрешна сървърна грешка

#### `PUT /api/reservations/{id}` — Редактиране на резервация

Позволява промяна на данните по резервация. Може да се редактира само резервация в статус **Pending**. При промяна на времето системата отново проверява дали залата е свободна. **Достъп: собственикът на резервацията или Admin.**

**Входни параметри (path):** `id` — идентификатор на резервацията.

**Входни параметри (тяло на заявката — JSON):**

| Поле            | Тип        | Задължително | Валидации                                            |
| --------------- | ---------- | ------------ | ---------------------------------------------------- |
| `startTime`     | `DateTime` | да           | трябва да е в бъдещето                               |
| `endTime`       | `DateTime` | да           | трябва да е след `startTime`                         |
| `purpose`       | `string`   | да           | минимум 5, максимум 200 символа                      |
| `attendeeCount` | `int`      | да           | минимум 1, не може да надвишава капацитета на залата |
| `notes`         | `string`   | не           | максимум 500 символа                                 |

**Изходни данни при успех (HTTP 200):** Обновен обект `ReservationResponse`.

**Грешки:** `400` — `401` — `403` — `404` — `409` новото време е заето — `500` вътрешна сървърна грешка

---

#### `DELETE /api/reservations/{id}` — Отмяна на резервация

Отменя резервация (задава `status = Cancelled`). Може да се отмени само резервация в статус **Pending** или **Approved**. **Достъп: собственикът на резервацията или Admin.**

**Входни параметри (path):** `id` — идентификатор на резервацията.

**Изходни данни при успех (HTTP 204):** Без тяло на отговора.

**Грешки:** `400` резервацията не може да се отмени (вече приключила или отхвърлена) — `401` — `403` — `404` — `500` вътрешна сървърна грешка

---

#### `PATCH /api/reservations/{id}/status` — Одобряване или отхвърляне

Позволява на администратора да одобри или отхвърли резервация в статус **Pending**. **Достъп: само Admin.**

**Входни параметри (path):** `id` — идентификатор на резервацията.

**Входни параметри (тяло на заявката — JSON):**

| Поле     | Тип      | Задължително | Валидации                                       |
| -------- | -------- | ------------ | ----------------------------------------------- |
| `status` | `string` | да           | само `Approved` или `Rejected`                  |
| `notes`  | `string` | не           | бележка от администратора, максимум 500 символа |

**Изходни данни при успех (HTTP 200):** Обновен обект `ReservationResponse` с новия статус.

**Грешки:** `400` — `401` — `403` — `404` — `500` вътрешна сървърна грешка
